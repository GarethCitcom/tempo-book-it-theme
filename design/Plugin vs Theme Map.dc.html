Plugin vs theme — responsibility map

The plugin will be sold to other dance schools, so the design line is drawn by one rule: the plugin owns everything inside its own surfaces, expressed through overridable design tokens; the theme owns the page around them. A tenant should get a coherent, branded booking experience from the plugin alone, on any well-behaved theme.

The rule of thumb

Plugin owns Everything rendered by its shortcodes, blocks and endpoints: layout, components, states, copy, interactions, tokens and their defaults. If removing the theme breaks it, it belongs in the plugin.
Theme owns The page around those surfaces: site header/footer, portal navigation, page templates, width of the content column, and any tenant CSS that overrides the plugin's tokens.
